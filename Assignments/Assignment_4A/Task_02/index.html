Trace: Incoming Message with Screen Off (Desk-Check)

Android Screen-Off Message Path:
1. Hardware/Baseband: LTE modem receives paging frame, raises hardware interrupt.
2. Kernel: Linux wakes, radio driver buffers packet, acquires partial wake-lock.
3. System Service: Google Play Services receives packet, verifies FCM token.
4. Framework: ActivityManager un-freezes app process or forks if cold.
5. Runtime: ART executes `FirebaseMessagingService.onMessageReceived()`.
6. Application: App decrypts message using local Keystore key and shows notification.
iOS Screen-Off Message Path:
1. Hardware/Baseband: Baseband processor receives APNs push packet.
2. Kernel: Mach kernel resumes `apsd` (Apple Push Service Daemon).
3. System Service: SpringBoard displays encrypted notification banner.
4. Runtime / Extension: If mutable content, OS launches lightweight `NotificationServiceExtension` sandboxed process.
5. Application: Extension decrypts payload using Secure Enclave key and renders preview.

Task 2.5: Challenge (App Terminated Due to Memory Pressure)

Prediction: On Android, FCM wake-up causes `Zygote` to fork a fresh process in background, executing the service without UI. On iOS, the main app remains dead; only the isolated `NotificationServiceExtension` is spawned with a strict 30MB memory ceiling.
