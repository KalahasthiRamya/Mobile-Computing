🔍 Task 1.1: Diagnose the Draft Architecture Note (2 Marks)

A junior engineer submitted an informal draft note. Here are 5 critical technical deficiencies:

Deficiency What is Missing or Ambiguous Why Another Engineer Cannot Build From It
1. Missing Subsystems Omits Hardware Abstraction Layer (HAL), native C/C++ libraries, and system daemon services. Drivers cannot be mapped to user space; IPC boundaries remain completely undefined.
2. Kernel Ambiguity States "a kernel sits in the middle and runs apps" without kernel type or IPC. Kernels do not run apps directly; they schedule threads and manage virtual memory. Binder/Mach IPC omitted.
3. Undefined Runtime Does not state whether execution is JIT, AOT, or interpreted bytecode. Compiler targets cannot be configured; memory management (GC vs ARC) is unknown.
4. Permission Enforcement Vaguely claims "OS keeps applications secure using permissions". Fails to specify who grants permissions (user at runtime vs package manager) and where enforced (SELinux, kernel DAC).
5. Battery Mechanism Claims "OS saves battery when needed" with zero triggers or states. No state-machine triggers (screen-off timers, motion sensors, wake lock policies, Doze thresholds).

🛠️ Task 1.2: Repaired Android Layered Architecture (3 Marks)

Explicit Component Mapping:
• Runtime: ART residing in Layer 3.
• Security Enforcement: Kernel-level UID separation + SELinux in Layer 1; Permission checks in Layer 4.
• Power Management: Linux CPU governor in Layer 1; DeviceIdleController (Doze) in Layer 4.

🛡️ Task 1.3: Architectural Design Defence (1 Mark)

Design Defence (≤ 100 words):
This specification replaces informal prose with a deterministic five-tier hierarchy possessing explicit functional contracts. Each layer defines precise unidirectional dependencies, exposing typed APIs upward and consuming lower abstractions. The kernel is located as a monolithic scheduler with Binder IPC drivers, while security enforcement is divided between kernel DAC/MAC and user-space framework checks. Power management couples high-level Doze state machines to low-level kernel DVFS governors. This enables an independent engineer to implement and instrument every subsystem without ambiguity.
