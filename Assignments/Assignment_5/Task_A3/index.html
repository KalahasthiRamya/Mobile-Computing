📐 Generic Framework: SCHEDULE_OR_EXECUTE(State)

ALGORITHM SCHEDULE_OR_EXECUTE(Task, DeviceState)
INPUT:
  Task, DeviceState
OUTPUT:
  ExecutionOutcome
BEGIN
  IF NOT CheckFeasibility(Task, DeviceState) THEN
    PRUNE_OR_SCHEDULE(Task, DeviceState.NextFeasibleWindow)
    RETURN OUTCOME_DEFERRED
  END IF

  Snapshot ← CAPTURE_REVERSIBLE_STATE(Task)
  TRY
    EXECUTE_WORK(Task)
    COMMIT_SUCCESS(Task)
    RETURN OUTCOME_SUCCESS
  CATCH FailureException
    ROLLBACK_TO_SNAPSHOT(Snapshot)  // Explicit Undo!
    REGISTER_RETRY_BACKOFF(Task)
    RETURN OUTCOME_FAILED
  END TRY
END

🛡️ Role of Undo / Cancellation (A3.3)

Why Undo is Mandatory:
In mobile systems, background tasks are routinely killed by the Android `LowMemoryKiller` (LMKD) or terminated when a user drives into a cellular tunnel.
• If a task marks local patient records as "IN_SYNC" and begins network transmission, but connection snaps mid-way without rollback, the records remain in limbo.
• Future sync routines assume the data was uploaded, resulting in PERMANENT SILENT DATA LOSS on the cloud server.
