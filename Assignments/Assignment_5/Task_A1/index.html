🏥 Constraint-Aware Intent & Service Architecture (Part A - 7 Marks)

Healthcare Monitoring Architecture:
• Worker Mapping: Periodic sensor acquisition → Coroutine Worker; Encrypted Cloud Upload → WorkManager Job with NetworkType.CONNECTED constraint.
• Inter-Component Intents: Explicit Intents for local ForegroundService updates; Ordered Broadcasts for emergency panic alerts.
• Pruning / Feasibility Test: If battery < 15% OR device in Deep Doze, defer non-vital uploads to maintenance window.

📜 SIMATS Architectural Pseudocode (A1.4)

ALGORITHM DispatchConstraintAwareWork(WorkQueue, SystemState)
INPUT:
  WorkQueue – pending telemetry and alert items
  SystemState – {BatteryPct, IsDoze, NetworkAvailable, EncryptionReady}
OUTPUT:
  ExecutionResult (EXECUTED, DEFERRED, or CANCELLED)
BEGIN
  NextItem ← PEEK(WorkQueue)
  IF NextItem.IsCritical THEN
    // Critical alert bypasses standard battery and Doze constraints
    ACQUIRE HighPriorityWakeLock(Duration: 3000 ms)
    START_FOREGROUND_SERVICE(EmergencyIntent(NextItem))
    POLL_DISPATCH(WorkQueue)
    RETURN EXECUTED
  END IF

  // Feasibility and pruning checks
  IF SystemState.BatteryPct < 15 AND NOT SystemState.IsCharging THEN
    DEFER_WORK(NextItem, Delay: 15_MINUTES)
    RETURN DEFERRED
  END IF

  IF NextItem.RequiresNetwork AND NOT SystemState.NetworkAvailable THEN
    REGISTER_NETWORK_CALLBACK(WorkManagerJob(NextItem))
    RETURN DEFERRED
  END IF

  ENQUEUE_BACKGROUND_WORKER(NextItem)
  RETURN EXECUTED
END
