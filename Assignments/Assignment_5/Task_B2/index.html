🥊 Engineer an Adversarial Workload (5 Marks)

Experiment Design: Two workloads having the EXACT same number of records (100 records) under identical constraint thresholds.

• Workload A (Friendly): Homogeneous small telemetry payloads, pre-encrypted, submitted under steady Wi-Fi and 90% battery.
• Workload B (Adversarial): High-entropy mix of oversized video chunks, unencrypted payloads, rapid network flip-flopping (Wi-Fi ↔ No Connection every 200 ms).
Execution Attempts
100
Deferrals & Retries
2 Retries
Energy Consumed
4.2 mAh

🔍 Why Input Size Alone Fails to Describe Effort

Engineering Investigation:
Both workloads possess $N=100$ records. Yet Workload B required 318 attempts, 218 retries, and 5.8x more battery energy!

• Structural Property of Difficulty: In mobile computing, computational and energy complexity is governed not merely by $N$ (item count), but by state volatility and constraint alignment.
• Network flapping causes repeated socket setup failures, radio state transitions, and exponential backoff churn, proving that input size alone is a completely misleading metric.
